# DESHI GEE — Autonomous Engineering Decisions Log

Decisions recorded while executing Final Prompt V5 (Stages 0–7) whenever implementation specifics were chosen using the V5 decision table (D1–D20) or fail-closed defaults.

| ID | Stage | Topic | Decision Made | Rationale / Reference |
|---|---|---|---|---|
| `DEC-01` | 0 / 4 | Gemini 4 thinking parameter for latency (D20) | Use `thinkingConfig: { thinkingLevel: ThinkingLevel.LOW }` on `gemini-4-hydrogen` instead of `thinkingBudget: 0`. | Per `@google/genai` Gemini 4 API rules, passing `thinkingBudget` to Gemini 4 models returns HTTP 400 (`INVALID_ARGUMENT`). `ThinkingLevel.LOW` minimizes reasoning latency cleanly without breaking the API. |
| `DEC-02` | 1 | `ownerConfirmedFields` schema on `store_settings/main` (D7, D8) | Represent unconfirmed fields as `unset` (`null` / `''` / `0`) in `DEFAULT_STORE_SETTINGS` AND add `ownerConfirmedFields?: Record<string, boolean>` with helper `isStoreFieldConfirmed(settings, field)`. If a store document loaded from Firestore explicitly sets non-placeholder values without `ownerConfirmedFields` (legacy doc), treat explicitly stored non-placeholder numbers/contacts as confirmed ONLY when `confirmedFromDb === true`, while code defaults (`DEFAULT_STORE_SETTINGS`) always have `ownerConfirmedFields = {}` (all unconfirmed). | Ensures zero code defaults leak into storefront UI, checkout, JSON-LD, or chatbot answers while remaining backward-compatible once the owner saves real settings in `/admin`. |
| `DEC-03` | 1 | Checkout availability when prices/fees are unset (D7) | Block order creation on both UI (`"Ordering not available yet"` / `"অর্ডার এখনও চালু হয়নি"`) and server (`POST /api/order`, `POST /api/orders/storefront` return `503`) whenever variant price or delivery fee is not owner-confirmed. | Fail-closed: never accept money or create an order using invented prices or fees. |
| `DEC-04` | 1 | Default chatbot `languageBehavior` (D1) | Default to `'bangla_script'` (maps seamlessly with existing `'prefer_bn'`/`'auto'` enum by supporting `'bangla_script' | 'mirror' | 'customer_choice'` with legacy aliases). | Matches V5 D1 directly while keeping admin switcher functional. |
| `DEC-05` | 1 | Policy pages/modals feature flag (D10) | Gate policy modal triggers behind `NEXT_PUBLIC_ENABLE_POLICY_DRAFTS === 'true'`; when visible, render prominent `"DRAFT – owner review required"` banner. Default off until owner reviews `docs/POLICY_REVIEW_LIST.md`. | Prevents unreviewed legal/refund promises from appearing as binding store policy. |
| `DEC-06` | 2 | Firebase Admin SDK initialization & fail-closed behavior (D4, D5) | Use Application Default Credentials (`applicationDefault()` / `initializeApp({ projectId })`) and explicit `getFirestore(app, firebaseConfig.firestoreDatabaseId)`. Assert database ID !== `(default)`. On permission/ADC error (`PERMISSION_DENIED` / `UNAUTHENTICATED` / missing ADC), throw `AdminSdkUnavailableError` and return HTTP `503` `"Ordering is temporarily unavailable"` — zero fallback to public-key REST writes. | Enforces D4 & D5 strictly with zero JSON service account keys. |
| `DEC-07` | 2 | Test-mode in-memory repository vs live Firestore (Hard Rule 2) | When `DESHI_GEE_TEST_MODE=1` (and `NODE_ENV !== 'production'`), unit/regression tests use injected/in-memory stores or Firestore Emulator (`FIRESTORE_EMULATOR_HOST`). Any attempt to touch live Firestore in tests throws `LiveFirestoreWriteBlockedInTestError`. Setting `DESHI_GEE_TEST_MODE=1` with `NODE_ENV=production` throws `ProductionTestModeForbiddenError` immediately. | Guarantees tests can never pollute live Firestore again. |
| `DEC-08` | 2 | Locked Firestore rules branch strategy (Hard Rule 1) | Keep `master:firestore.rules` untouched (matching live deployed rules, with deploy-blocked notice) and write the final locked-down Admin-SDK rules on branch `rules-final-admin-sdk` plus `docs/rules-proposals/firestore-final-admin-sdk.rules`. | Respects Hard Rule 1 (no live deploys; keeps running preview aligned with live rules until owner grants IAM and approves deploy). |
| `DEC-09` | 2 | Tracking token & fallback lookup security (D14) | Mint 192-bit (24-byte) CSPRNG `trackingToken` (`base64url`), store only its keyed HMAC-SHA256 hash (`trackingTokenHash`) on `orders/{orderId}`, return the raw token once in the order confirmation response & `/track?t=...` link. `POST /api/orders/track` accepts either `trackingToken` OR `orderNumber + phone` (per-IP & per-order rate limited, uniform `404` error). | Eliminates `{orderNumber}_{phone}` enumeration oracle completely. |
| `DEC-10` | 4 | Voice dictation & TTS default state (D15) | Keep voice dictation and assistant TTS **OFF by default** (`enableVoiceFeatures: false` in config & UI). Only show when explicitly enabled, with privacy notice, editable transcript (never auto-submitted), and daily cost cap. | Matches V5 D15 and prevents surprise voice costs or accidental order submissions. |
| `DEC-11` | 5 | Payment & Courier provider interfaces + 4-04 URL allowlist | Exported clean `PaymentProvider` / `CourierProvider` interfaces with deterministic mock providers alongside live SSLCommerz/bKash and Steadfast/Pathao/RedX implementations; enforced `isSafeCourierTrackingUrl` strict HTTPS allowlist on all courier tracking links. | Allows full CI/local testing without live credentials while blocking phishing/javascript: tracking links. |
| `DEC-12` | 5 | Gemini failover classification & cost table | Failover runs on transient errors (429/5xx/timeout/network) and retired-model 404; 401 and billing/key 403 fail closed (`shouldFailover: false`) and surface explicit `adminAlertCode` (`gemini_auth_failed` / `gemini_model_retired`). `estimateGeminiCostUsd` reads per-model `GEMINI_MODEL_COST_RATES_JSON` with scalar env fallback. | Prevents silent auth failures in production and supports env-only model rollback and accurate cost tracking. |
| `DEC-13` | 6 | T1.6 Structured Chat Turn Contract | Added `buildStructuredChatTurnContract` in `src/lib/chatbot/responseContract.ts` and emitted `meta.contract` additively on `/api/chat` NDJSON responses with backend-only verified money/orderId/status projection. | Preserves existing streaming UX while providing a strict backend-grounded response contract. |
